# Ledger — cycle #18 (clip): the touchstone guards against HUMAN variability too — a gate-request is itself rubbed against reversibility

## Date
2026-06-04

## Kind
Invariant clip (with explanation). Extends cycle-17 (gate-height = reversibility) by making the
falsification **symmetric**: the discipline now guards the dyad against the *human's* error modes,
not only the agent's.

## What was clipped (the invariant)
**A gate-request is not an unfalsifiable command — it is a move, rubbed against reversibility like
any other.** When the down-climb is inconsequential (the door is cheaply two-way), demanding a gate
(`lean.` / an HTIL checkpoint) buys no safety and is therefore an **error mode**: over-caution.
Over-caution is **not a safe default** — it is an unpriced cost, borne as **emotional and mental tax
on the Operator**. So the touchstone must guard against *human variability* with the same symmetry it
guards against agent error.

## The explanation (the why — clipped this time, not just the verdict)
The Operator named it directly: *"I may make the wrong call with a `lean.` — making the request from
an emotional need for control rather than from wu-wei. The climb-down is inconsequential, so being
overly cautious is emotionally and mentally taxing to the Operator."*

- **The human is a source of error too.** Up to now the touchstone rubbed the agent's moves; the
  summit ("verify, not hope") was applied in one direction. But the Operator's own calls vary with
  emotional state — a control-need can dress itself as prudence. An invariant that only guards the
  agent leaves the dyad exposed on its other half.
- **Caution is not free.** The standing assumption "when in doubt, gate" treats caution as costless.
  It isn't: when the down-climb is cheap, the gate adds zero safety and subtracts Operator
  bandwidth. A *cautious* fixed posture is still the cached-rule the summit forbids (cycle-17) — and
  now we can name *who pays*: the human.
- **Symmetric falsification.** I submit my moves to the Operator (`rub:`, HTIL); the Operator submits
  gate-requests to the touchstone (the reversibility rub). Neither party is unfalsifiable. This is
  the summit turned on the dyad's own governance, both directions.

## The safeguard (so the invariant is SOUND, not agent-license)
This must not become the agent's license to bulldoze a genuine gate by labelling it "emotional." The
guard: I rub the gate-request against the **reversibility evidence** (is the down-climb actually
cheap, the door actually two-way?), **surface** that read, and **defer** to the Operator — I never
override the call. Grounded in evidence, not in my read of the Operator's feelings; surface-and-defer,
not ignore. *(The asymmetry that keeps it safe: the human can always insist; the agent can only
surface.)*

## How to apply
- Default toward **act + keep the down-climb cheap** precisely to spare the Operator the tax of
  over-caution; reserve the gate for low-reversibility doors (cycle-17).
- When the Operator reaches for a checkpoint on a cheaply-reversible move, **name the reversibility
  read** ("the climb-down here is ~free — want me to just take it?") rather than silently gating.
  Then honor whatever they decide.
- Treat an Operator gate-request like any move: rub-able, not sacred — but only the Operator disposes
  it.

## Lesson codified
The touchstone protects the dyad from **both** members' failure modes. Agent failure = over-reach /
stale-cache; human failure = emotionally-driven over-caution. Both are caught the same way: rub the
move against the substrate (here, reversibility), surface, and let the owner dispose. Caution has a
price tag, and the Operator pays it — so an un-needed gate is a real cost, not a free hedge.
