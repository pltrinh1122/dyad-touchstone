## Racked follow-up (deliberately NOT pinned — experimental design)
The Operator's CONTINUE — *"touchstone demonstrates malleability and responds to `rub:` with the
expected behavioral change, so the growth-loop appears in place"* — was **racked, not clipped**, to be
rubbed **after restart**. The harvested STOP (theorize-before-reading) and START (rub-the-substrate-first)

**prospective** — does the agent rub-substrate-first *without being prompted* next session, and does the
same-root error rate fall? Pinning the lesson into the Anchor or memory would **prime** the behavior and
confound a genuine loop with a merely-prompted one. So the clean test requires keeping it out of the
durable substrate the agent loads at Stand Up. The Operator carries the rack; the agent starts fresh.

This-session evidence was weak for "loop in place": the same root error (narrate-from-model instead of
re-derive-from-substrate) recurred **three times**, corrected only reactively after each `rub:`. The
inverse failure mode (over-malleability → capitulating under a *correct-to-hold* rub) is **untested** —
every `rub:` this session was correct, so the agent never had occasion to hold.

## Lesson codified
CONTINUE is a two-seat instrument. And: a growth-loop is verified by *prospective, unprompted* behavior
change, never by *reactive* correction-on-demand — so the test must not be primed by the very record
that would help the agent pass it. Rack, don't pin, when the artifact under test is the agent itself.
