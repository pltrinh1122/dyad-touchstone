## The clipped verdict — the taxonomy

Two **orthogonal axes**, plus two terms that are deliberately **not** taxa.

- **SYSTEM** (genus, by failure-space): **agent** (open / model-directed) · **automaton**
  (closed / deterministically-checkable). The two columns of the durability×failure-space 2×2.
- **FUNCTIONALITY** (nests under system; for agents = the **principal** axis — *who do you
  answer to?*):

  | principal | functionality | constitution |
  |---|---|---|
  | a human — **seat** | **partner** | **dyad** (partner + self-authored substrate + G-bound-to-V) |
  | a human — **user** | **assistant** | non-dyad (thin: property 1 absent) |
  | another agent | **worker** (spawned sub-agent) | non-dyad |
  | none | **autonomous** (unbonded + unspawned) | non-dyad |

  Automata: single-shot = **tool** · durable code-path orchestration = **workflow**.

- **Not taxa** (each was a candidate that the rub re-sorted to its native level):
  - **orchestration** (orchestrator-vs-worker) — a **re-derived call-graph position** ("does
    this node delegate to children?"), not a stored kind. Minting it would violate
    single-home #2 (*status is never stored, only rubbed*). Read it off the graph.
  - **bot** — the **vernacular umbrella** for the whole tree; the field migrated bot→agent
    precisely to escape its vagueness. Re-adopting it inward is regressive.

**The lock:** `assistant | partner` is **property 1 restated** — DYAD.md property 1 reads
"a **seat**, not a **user**." So `partner = seat`, `assistant = user`; the dyad is the
**partner** (the seated one) with properties 2-3 making the seat survive a restart. This
pair is *entailed* by the constitution, not merely consistent with it — the one cell the
formalization predicts rather than permits.
